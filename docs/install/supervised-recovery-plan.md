## Outcome and assumptions

Keep the existing fresh-Mac command source-compatible:

```sh
curl -fsSL https://raw.githubusercontent.com/teazyou/workspace/master/scripts/installs/bootstrap.sh | bash
```

The implemented bootstrap prepares a small local toolset, prints `Step1done` and a complete copyable prompt, then **exits without invoking `installation.sh`**. The human signs in to one working AI option. That AI works directly in the main session to restore the remaining scripts and documented manual extras, checks their outcomes, and diagnoses failures before continuing. A successful shell exit alone will never mean the whole Mac is restored.

Considered assumptions:

- “Both CLI claude desktop and chatgpt desktop” means **both desktop applications and both actual terminal agents**: Claude Desktop + native Claude Code; ChatGPT Desktop + Codex CLI. Both paths are installed so only one provider/account needs to be usable. Subscription, account entitlement, regional access, and local permissions remain human/account preconditions; installing an app cannot establish them.
- The acceptance target is a fresh **Apple Silicon Mac on macOS 26**, with an administrator account, internet, and stock Terminal. Other supported macOS releases can reach minimum readiness after compatibility checks, but shortcut restoration is version-gated and the current VPN has narrower path assumptions. Intel must be reported as a separately unverified path, not silently included in the promise. Current Homebrew documentation lists Intel as Tier 3 and macOS 15+ as its supported OS baseline. [Homebrew requirements](https://docs.brew.sh/Installation)
- iTerm “ready” in phase 1 means its application is installed and structurally verified, ready for the human to open with the stock shell. Workspace preferences, fonts, Oh My Zsh, NVM, and the managed `.zshrc` belong to phase 2. No full shell stack is needed to launch either native CLI.
- All recovery work runs directly in the main AI session: inspection, commands, repairs, verification, and communication. Do not delegate to agents. Either installed CLI is suitable; no particular model is required.
- Brave is **application-only** for human sign-in. Do not recreate Brave profile/preferences capture, helper scripts, bookmarks, browser-data symlinks, sync tokens, or public account material. Existing Google Chrome remains in the full package set.

## Phase 1: minimum bootstrap and an explicit stop

### Ordered work

1. **Piped entry and environment.** Preserve Bash 3.2 compatibility and the `/dev/tty` handoff that prevents an installer consuming its own pipe. A failed self-download, unavailable controlling terminal, invalid source, or interruption must fail with a concrete rerun message, not continue “with fingers crossed.” Use controlled temporary files and cleanup traps; stop any sudo keepalive on every exit. Do not load the existing login shell or source `.zshrc` to discover PATH.
2. **Preconditions and CLT.** Confirm macOS, architecture, administrator access when installation needs it, network, and sufficient disk for the minimum toolset. Request the system CLT dialog when needed. Poll with a visible elapsed status and a documented finite deadline (30 minutes); cancellation/time expiry exits resumably. Verify `xcode-select -p` and an actual CLT tool (`xcrun --find clang` and `xcrun --find swift`), not just the selected-path string. Full Xcode/App Store sign-in is deferred. Native phase-1 packages do not justify unconditional Rosetta; defer it unless current selected artifacts demonstrably require x86 execution on arm64. Never use a running `oahd` process as the sole installed-state check.
3. **Homebrew and Git.** Reuse the official Homebrew install route and scoped sudo handling. Resolve the architecture-appropriate executable at `/opt/homebrew/bin/brew` or `/usr/local/bin/brew`; verify its prefix/version, initialize `shellenv` for each installer process, and ensure Brew Git works. Detect an unexpected prefix/architecture or a shadowing executable and stop for diagnosis. Do not install the full formula/cask list here.
4. **Resolve and validate one published repository revision.** Use the trusted public HTTPS origin `https://github.com/teazyou/workspace.git` and resolve `master` once after Git is available. Freeze that full commit ID for the clone, code, guide, and printed handoff. Re-fetch the bootstrap source from that immutable revision and compare it with the executing downloaded source before sourcing repository helpers. If branch movement produced a mismatch, stop and rerun; do not mix versions. The initial command remains a trust decision in the publisher’s HTTPS `master` script, not cryptographic proof of an independently trusted release.
5. **Checkout handling.** If `~/workspace` is absent, clone without initially running repository code, check out the resolved revision, and verify expected origin, commit, and required files. If the path exists, distinguish a Git checkout/worktree, a symlink, and a conflicting directory/file. Never `reset`, `clean`, `stash`, unstage, overwrite, or force-pull user work. Accept an existing checkout automatically only when it has the expected trusted origin/revision and all recovery-relevant scripts, helpers, guides, policies, and configuration sources match that revision. Read Git objects with replacement refs disabled so the published commit cannot be locally substituted during verification. Unrelated local modifications can remain. A stale/different revision, changed recovery source, unexpected origin, path redirection, or untracked shadow file produces a diagnostic stop and preserves everything; updates require a separately reviewed action. A missing guide never falls back to running the old full installer.
6. **Install minimum packages from the single inventory.** Select only `iterm2`, `chatgpt`, `claude`, `codex`, and `brave-browser` after Git. No full-install tap, Python, NVM, Node, fonts, window manager, preferences, or app-account data. Add a narrow CLI-only invocation to `install_claude.sh`, and use it after successful Desktop verification. If the Claude Desktop cask fails, stop minimum readiness; its Python-dependent native fallback belongs to supervised diagnosis, not hidden minimum expansion. All requested minimum targets must pass before printing `Step1done`, even though only one provider must later authenticate.
7. **Verify and print.** Check package presence and actual artifacts independently, execute both CLI `--version` checks by absolute path, and check the guide contract/revision. Print each application path, both concrete CLI launch commands, verified Git revision, guide path, and the reusable prompt below. Print `Step1done: minimum applications and terminal agents are installed. Sign in to either Claude Code or a local Codex-capable ChatGPT session, then paste the prompt below.` Say explicitly that authentication and remaining setup are pending. Exit; no model call, app login, full installer, or background continuation.

## Failure, rerun, and authorization rules

- Keep a concise non-secret task record: trusted revision, current step, actual checks, failure, repairs, and remaining human gates. A private local transcript/log may be retained outside the public repository with restrictive permissions. No persistent checkpoint mechanism, service, scheduled task, or whole-machine snapshot is proposed. Never log secrets or enable shell tracing around private operations.
- Bootstrap stops on the first unresolved prerequisite/readiness failure. Allow at most one diagnostic retry of a failed download/install after a concrete transient cause or repair; no infinite retries. Human-driven CLT/App Store downloads can take longer than other commands, but have visible progress, a finite wait/deadline, and an interruption-safe rerun message.
- Phase 2 permits the documented setup and the smallest local repair needed to achieve its intended behavior. Repair the managed source, not an unmanaged mirror; update the map and affected guide. Preserve unrelated edits and inspect diffs before/after each repair. Data deletion, forced Git operations, unrelated packages, credential rotation, security-policy weakening, and publication require separate authorization. A current script containing a broad operation does not make that operation automatically safe on an existing machine.
- A failed row remains failed until evidence passes. Retry its scoped script at most once after diagnosis/repair. If still failing, report the cause and preserve state; continue only rows without that dependency. Never delete an app, NVM tree, configuration directory, VPN profile, or user database as a routine rerun strategy.
- Re-running phase 1 checks current artifacts/revision rather than relying on a marker. Its strict published-source gate may reject changes made during phase 2; explain that rejection and resume the reviewed phase-2 session instead of erasing legitimate repairs or activation changes. Re-running phase 2 reconciles the original handoff revision with recorded authorized diffs, checks row outcomes, and resumes unfinished work. Native app/CLI updates and Brew receipts need separate care; no second installation to “fix” PATH. A broken app with an existing receipt requires a diagnosed repair reviewed in the main session; new human permission is needed only at the boundaries above.
- Protect the active AI/terminal/browser host. No blanket Brew upgrade while it supervises. Before iTerm quit, AI-app replacement, logout/reboot, or a VPN test, establish a working alternative session and save the current non-secret step. If the only usable host cannot survive, defer the interruption until the user can resume. Maintenance is optional follow-up, not a prerequisite for calling configured installed targets verified.
- Keep removed checkpoint, second-brain, PostgreSQL, and old handoff work removed. No Brave-data restoration. No SIP disablement, permissive blanket tool flags, Gatekeeper bypass, or automatic security approvals.
