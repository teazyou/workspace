System prompt rewrite paths

  2. Plugin experimental.chat.system.transform — output {system: string[]} full replace/augment; system[0] zero-key = wholesale override.
  3. PromptInput system string appended as extra system message (SDK) — NOT a rewrite.

No config key system_prompt (verified vs https://opencode.ai/config.json).

AGENTS.md

Requested events

  • post tool use = post_tool_call (also fires status:"blocked");
  • session start = on_session_start (+ on_session_end / on_session_finalize / on_session_reset);

Data contract

stdin JSON: {hook_event_name, tool_name, tool_input, session_id, cwd, extra: per-event kwargs}.

stdout: block {"decision":"block","reason":…} (CC) or {"action":"block","message":…}; modify {"action":"modify","args":…} / {"decision":"modify","tool_input":…}; context {"context":"…"} for pre_llm_call; continue {"action":"continue"}.

Exit code 2 = block on pre_tool_call (message = stdout JSON → first 400 chars stderr → generic).

Limits

  • Blocking ONLY pre_tool_call; fail_closed only pre_tool_call; matcher only pre/post_tool_call.
  • subagent_start observer-only (can't edit child prompt — block delegation via pre_tool_call on delegate_task).
  • No PreCompact/PostCompact/StatusLine.
  • Command syntax: hooks in ~/.hermes/config.yaml (JSON .claude/settings.json NOT read).
  • Consent: hooks_auto_accept / --accept-hooks / HERMES_ACCEPT_HOOKS=1 / allowlist ~/.hermes/shell-hooks-allowlist.json.

Recommendation

RECOMMENDED STRATEGY Single realistic strategy: thin adapter script per harness + one shared core. Each harness gets a minimal shim (hooks.json entry for DSH, tiny JS plugin wrapper for OpenCode, YAML command entry for Hermes) that serializes the same JSON event envelope and invokes a shared core (plain POSIX/Node shell or a CLI tool) — Do NOT write three full feature sets.
  • DSH = richest (native Cordis plugins + bridge, block via exit 2, additionalContext inject, profile/--patch overlays);
  • OpenCode = mutate via output in JS only (no subprocess bridge without a long-lived server process);
  • Hermes = gateway/plugin hooks for logic-heavy work, shell hooks for simple command shims.

Max-compat cuts (what must be dropped)

DROP: SUBAGENT-START PROMPT EDITING NOT possible in Hermes (observer-only) or OpenCode (no agent.start); only DSH supports it. For compat, treat subagent-start as informational/log-only.
DROP: PostToolUse updatedToolOutput NOT honored in DSH (parsed, warned, ignored).
DROP: PreToolUse allow/defer/updatedInput Unsupported in DSH.
DROP: after-AI-answer message edits experimental.text.complete is OpenCode-only (experimental, can rewrite); DSH has no equivalent message-edit hook — fall back to Stop/agent/turn-stopping.
ADAPT: user-submit handling Hermes offers no distinct event — use pre_llm_call and gate on context.
ADAPT: injection strategy must be per-harness None of the three share an injection channel (additionalContext user message / output.parts+session.prompt / context:{} JSON).
